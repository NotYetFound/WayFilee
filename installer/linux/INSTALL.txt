WayFilee for KDE Plasma Wayland on Linux
========================================

Run ./Filee to try the extracted application. Run ./filee-cli help for the CLI.
The application uses Avalonia's native Wayland backend and needs a KDE Plasma
Wayland session. There is no X11 fallback.

Install for the current user with ./install.sh. This installs a desktop launcher,
a wayfilee CLI link in ~/.local/bin, and the WayFilee KWin script that positions
the donut at the pointer. It does not need root. Use ./install.sh --upgrade for
an existing installation, or ./uninstall.sh to remove the application. Settings
and converted files are preserved. The installer refuses to replace files or
KWin script directories that it did not create.

Fedora/Nobara dependencies:
  sudo dnf install python3 libinput systemd-libs libwayland-client \
      fontconfig freetype

On Ubuntu, Debian, Arch, and other KDE distributions, install the equivalent
Python 3, libinput, libudev, Wayland client, fontconfig, and FreeType packages.
Package names vary by distribution and release. The repository's
docs/PORTABILITY_AUDIT.md lists what remains to validate before native distro
packages are released.

The .NET runtime is bundled in the release archive. Optional conversion engines
can be installed through the app's Engines page or provided by the system.

The archive install can update itself through the app after verifying the new
release checksum. RPM/DEB/Arch installs fetch a verified matching package from
GitHub Releases and ask the system package manager to install it. A GitHub
Release does not make WayFilee appear in Discover's ordinary update list.

Global Ctrl+drag gestures need read access to /dev/input/event* devices. The
app does not change system permissions. If you choose to grant access, your
account can read all keyboard and pointer input, including input in other apps:
  sudo usermod -aG input "$USER"
Sign out and back in for group membership to take effect. On systems where
/dev/input uses another ACL policy, grant access through that policy instead.
Without this permission, the drop zone and Dolphin context action still work.

In KDE System Settings, check that the "WayFilee donut at cursor" KWin script
is enabled. The installer enables it on first install and asks KWin to reload.
If the donut opens in the wrong place, sign out and in after installation.

Known Wayland limitation: the app cannot identify the window under the pointer.
A drag gesture scoped to the file manager may also start over another app, and
the excluded-app list cannot filter it. The menu only accepts file drops, but
it can affect another drag when opened there. Adjust the modifier in Triggers
if needed. Real input gestures and KWin placement still need testing on each
supported Plasma version.

  https://develop.kde.org/docs/plasma/kwin/api/
